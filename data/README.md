# Данные

В проекте используется открытый датасет **Online Retail**, содержащий транзакции интернет-магазина за период с **1 декабря 2010 года по 9 декабря 2011 года**.

## Источник данных

Исходный датасет:

**Online Retail — UCI Machine Learning Repository**

Набор данных содержит информацию о заказах, товарах, клиентах и странах покупателей.

Исходный файл предоставляется в формате:

```text
Online Retail.xlsx
```

Файл не включён в репозиторий из-за его размера.

## Структура данных

Исходный набор содержит следующие поля:

| Поле          | Описание              |
| ------------- | --------------------- |
| `InvoiceNo`   | Номер заказа          |
| `StockCode`   | Код товара            |
| `Description` | Описание товара       |
| `Quantity`    | Количество товара     |
| `InvoiceDate` | Дата и время операции |
| `UnitPrice`   | Цена единицы товара   |
| `CustomerID`  | Идентификатор клиента |
| `Country`     | Страна                |

Размер исходного набора данных:

* **541 909 строк**
* **8 столбцов**

## Подготовка данных для MySQL

Для загрузки данных в MySQL исходный Excel-файл преобразуется в CSV.

В проекте используется следующий формат CSV:

* кодировка: `UTF-8`;
* разделитель столбцов: `;`;
* десятичный разделитель: `,`;
* формат даты: `DD.MM.YYYY H:MM`.

Пример строки:

```text
536365;85123A;"WHITE HANGING HEART T-LIGHT HOLDER";6;01.12.2010 08:26;2,55;17850;United Kingdom
```

После преобразования файл рекомендуется сохранить как:

```text
Online Retail.csv
```

## Загрузка в MySQL

Путь к CSV-файлу указывается в файле:

```text
sql/02_data_import.sql
```

В проекте используется команда `LOAD DATA LOCAL INFILE`.

Пример:

```sql
LOAD DATA LOCAL INFILE 'D:/Online Retail.csv'
INTO TABLE online_retail_import
CHARACTER SET utf8mb4
FIELDS TERMINATED BY ';'
ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 ROWS;
```

Путь к файлу необходимо изменить на путь к файлу на локальном компьютере.

## Обработка данных

После загрузки CSV данные сначала помещаются в промежуточную таблицу `online_retail_import`.

Затем они преобразуются и переносятся в `online_retail_raw`.

На этом этапе:

* `Quantity` преобразуется в целое число;
* `InvoiceDate` преобразуется в `DATETIME`;
* `UnitPrice` преобразуется в числовой формат;
* пустые значения `CustomerID` преобразуются в `NULL`;
* из `Country` удаляются лишние символы конца строки.

Дальнейшая проверка качества и очистка выполняются в следующих этапах проекта.

## Важные особенности данных

Исходный датасет содержит ряд особенностей, которые учитываются при анализе:

* отсутствующие значения `CustomerID`;
* отменённые заказы с префиксом `C` в `InvoiceNo`;
* отрицательные значения `Quantity`;
* нулевые и отрицательные значения `UnitPrice`;
* полные дубликаты;
* экстремальные значения количества;
* служебные операции, представленные отдельными кодами товаров.

Поэтому исходные данные не используются непосредственно для расчёта основных показателей продаж.

Для основного анализа формируется отдельная таблица `online_retail_clean`, в которую попадают операции, удовлетворяющие условиям:

```sql
Quantity > 0
AND UnitPrice > 0
```

При этом исходная таблица `online_retail_raw` сохраняется и используется для анализа возвратов и отмен.

## Примечание

Данные используются исключительно в учебных и демонстрационных целях для построения портфолио-проекта по анализу данных.
